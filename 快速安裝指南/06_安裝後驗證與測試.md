# 06 安裝後驗證與測試

本文件提供完整的安裝後驗證清單，讓你逐步確認每個服務正常運作。請依序執行，所有項目通過後再進行端對端測試。

---

## 服務狀態檢查清單

### 1. Docker 容器狀態

```bash
docker ps
```

預期看到兩個 `Up` 狀態的容器：

| NAMES | IMAGE | PORTS |
|-------|-------|-------|
| `pg_container` | postgres | 0.0.0.0:65432->5432/tcp |
| `ai-qa-n8n` | n8nio/n8n | 0.0.0.0:5681->5678/tcp |

若容器狀態為 `Exited`，執行以下指令查看錯誤：

```bash
docker logs pg_container
docker logs ai-qa-n8n
```

### 2. PostgreSQL 資料庫

連線測試並確認資料表已建立：

```bash
psql -h localhost -p 65432 -U testuser -d vectordb -c "\dt"
```

預期看到以下 8 張資料表（依字母排序）：

```
 Schema |         Name          | Type  |  Owner
--------+-----------------------+-------+----------
 public | allowed_users         | table | testuser
 public | conversation_sessions | table | testuser
 public | document_chunks       | table | testuser
 public | document_contents     | table | testuser
 public | document_permissions  | table | testuser
 public | documents             | table | testuser
 public | processing_logs       | table | testuser
 public | qa_logs               | table | testuser
```

若資料表不完整，重新執行 schema 建立指令：

```bash
psql -h localhost -p 65432 -U testuser -d vectordb -f n8n自動存入資料庫/02_postgresql_schema.sql
```

### 3. pgvector Extension

確認向量擴充套件已正確安裝：

```bash
psql -h localhost -p 65432 -U testuser -d vectordb \
  -c "SELECT extname, extversion FROM pg_extension WHERE extname='vector';"
```

預期回應：

```
 extname | extversion
---------+------------
 vector  | 0.7.0
```

若無回應，表示 pgvector 未安裝，需重新初始化資料庫容器。

### 6. ngrok Tunnel

確認 ngrok tunnel 已建立並取得公開 URL：

```bash
curl http://localhost:4040/api/tunnels
```

預期回應中包含 `public_url` 欄位，例如：

```json
{
  "tunnels": [
    {
      "name": "command_line",
      "public_url": "https://xxxx-xx-xx-xx-xx.ngrok-free.app",
      "config": {
        "addr": "localhost:8765"
      }
    }
  ]
}
```

若 tunnel 未啟動：

```bash
ngrok http 8765
```

取得 `public_url` 後，必須更新 LINE Developers Console 中的 Webhook URL：

```
https://xxxx-xx-xx-xx-xx.ngrok-free.app/webhook
```

### 7. n8n 工作流

1. 開啟瀏覽器，前往 `http://localhost:5681`
2. 登入 n8n（預設帳號/密碼見安裝文件）
3. 進入 **Workflows** 清單
4. 確認 `LINE QA Assistant` 工作流已匯入
5. 確認工作流狀態為 **Active**（綠色開關）

若工作流未匯入，在 n8n 介面執行匯入：

- 點選 **Import from file**
- 選擇 `workflows/qa_workflow.json`

### 8. 端對端測試（LINE Bot 測試）

完成上述 1～7 項後，進行實際 LINE 對話測試：

**測試 1：基本問候**
- 在 LINE 對機器人傳送：`你好`
- 預期回覆：機器人正常回應問候語

**測試 2：Quick Reply 選單**
- 傳送：`找檔案`
- 預期回覆：出現 Quick Reply 選單，包含功能選項

**測試 3：問答功能**
- 傳送任意業務相關問題
- 預期回覆：根據知識庫內容回答，或提示查無資料

---

### 9. 向量搜尋功能測試

直接呼叫 API 測試向量搜尋端點：

```bash
curl -X POST http://localhost:8765/vector-search \
  -H "Content-Type: application/json" \
  -d '{"question":"測試問題","top_k":3,"min_sim":0.1}'
```

預期回應（無資料時）：

```json
{"chunks": [], "count": 0}
```

若回應包含 `chunks` 陣列（非空），表示知識庫已有資料，搜尋功能正常。

> **說明**：回應 `count: 0` 是正常的，代表 API 運作正確但知識庫尚無資料。執行文件匯入流程後，再次測試應有結果返回。

### 10. 授權用戶確認

查詢目前已授權的 LINE 用戶：

```bash
psql -h localhost -p 65432 -U testuser -d vectordb \
  -c "SELECT line_user_id, display_name, role, is_active FROM allowed_users;"
```

若結果為空，機器人將拒絕所有用戶的請求。**必須新增至少一個授權用戶**，詳見下方說明。

---

## 新增授權用戶（必要步驟）

### 取得 LINE User ID

LINE User ID 格式為 `U` 開頭的 33 字元字串，例如：`Uxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`

**取得方式：**

1. 在 n8n 的 `LINE QA Assistant` 工作流中，於 LINE Webhook 節點後方暫時新增一個 **Debug 節點**
2. 儲存並啟動工作流
3. 以你的 LINE 帳號傳訊息給 bot
4. 在 n8n 的 Executions 紀錄中，找到 Debug 節點輸出
5. 找到 `events[0].source.userId` 欄位的值，即為你的 LINE User ID

### 新增用戶 SQL

```sql
INSERT INTO allowed_users (line_user_id, display_name, role, is_active)
VALUES ('U你的LINE_USER_ID', '你的姓名', 'user', true);
```

**角色說明：**

| role | 說明 |
|------|------|
| `admin` | 管理員，可查詢所有部門資料 |
| `user` | 一般用戶，依部門權限查詢 |

新增後，重新傳訊息給 bot 確認授權生效。

## 常見問題對照表

| 問題現象 | 可能原因 | 解決方法 |
|---------|---------|---------|
| Docker 容器 Exited | 記憶體不足 / port 衝突 | `docker logs <container>` 查看錯誤；確認 port 65432、5681 未被佔用 |
| API Server 無回應（502） | Python server 未啟動 | 執行 `python scripts/api_server.py` |
| LINE Bot 完全無回應 | ngrok tunnel 未啟動，或 Webhook URL 未更新 | 確認 ngrok 正在執行；至 LINE Developers Console 更新 Webhook URL |
| LINE Bot 回應「查無授權」 | LINE user ID 未加入 allowed_users | 執行 `INSERT INTO allowed_users...` |
| 向量搜尋一直回傳空陣列 | 知識庫無資料，或 Embedding 維度不符 | 確認已執行文件匯入流程；確認 embedding 模型維度為 1024（bge-m3） |
| 模型回覆亂碼或無意義內容 | Ollama 模型名稱不正確 | 執行 `ollama list` 確認模型名稱；確認 n8n 工作流中的模型設定一致 |
| pgvector 查詢報錯 | Extension 未安裝 | 確認 `pg_extension` 中存在 `vector` |
| n8n 工作流無法啟動 | 缺少環境變數或 Credentials | 至 n8n Settings > Credentials 補齊 LINE、PostgreSQL、Ollama 連線設定 |
